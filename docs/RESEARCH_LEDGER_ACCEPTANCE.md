## Implemented flow and boundaries

The shared pure model validates exact source projections, immutable version/event chains, chronological recording order, public declarations and complete edition pins. One deterministic projection supplies the readable ledger, current qualification/problem states, Progress Report and API. An explicit UTC interval describes 2026-to-capture progress; no January baseline was recorded, so starting states remain unknown. Known present open/draft states are not backdated to January. The one editorial merge is a dated backfill, with its actual occurrence and later recording times shown separately.

The static view supports a current overview, individual records/versions, pinned editions, inert source text and complete JSON/event CSV. Record/edition IDs are encoded through shared helpers. Download routes use `/research-ledger/editions/<encoded-id>/ledger.json`, `ledger.csv` and `/research-ledger/sources/<encoded-id>/source.txt`; bounded route interaction has browser evidence below; complete download-byte and final publication proof remain part of acceptance. Source text is escaped/inert, not executed as Markdown or code. All server-rendered records remain reachable without JavaScript; optional filters/pagination alter the view, not the complete downloads. Two new dataset names, `research-ledger` and `research-progress`, use a pinned capture date rather than the API build clock; existing endpoint behavior stays separate.

Covered entry review and problem status must equal the model's current qualification/effective state. Uncovered reviewed frontmatter fails until registered, while uncovered drafts retain an ordinary draft label. This prevents a scalar reviewed flag from bypassing the ledger. The manifesto route aliases the same manuscript identity rather than creating another record. R2/R3 keys, all private browser work and shared OS records remain separate.

Ordinary whole-entry review requires an actual independent human source/framing statement and documented target authorship. Journal peer-reviewed wording additionally needs two distinct eligible independent human peer-review statements. Scientific disposition requires reviewed qualifying research and an exact independently reviewed decision, with at least two distinct eligible identities across those scopes. Self/alias/conflicted/unknown declarations do not acquire eligibility from a checkbox. The inspected public statements, identities, source reading and independence remain human responsibilities; the validator can only check the recorded declarations and relationships. Full rules are in [CONTRIBUTING.md](../CONTRIBUTING.md).

Withdrawal or newly disqualifying evidence immediately removes current support, with an `under-review` problem state and draft source-review fallback where required, without demanding replacement science. Earlier decisions and old editions remain historical. No issue closure or editorial artifact solves a problem, and no ledger qualification authorizes charity ratings.

## Source capture and future editions

Data lives in `src/data/research-ledger/` as a manifest and file-per-object JSON. Zero actors/reviews produce no placeholder files or required empty directories; the shared [read-only loader](../src/lib/research-ledger-data.mjs) yields empty arrays for absent groups, and the model checks necessary closure. It rejects unknown paths, unsafe files and invalid UTF-8 within bounded admission. It imports no CLI, Git or provider code and reads nothing at module import.

The explicit [capture CLI](../scripts/capture-research-ledger.mjs) reads local Git only when deliberately invoked. Default mode previews; writes require an explicit committed `--baseline-ref`, compare every covered working-source byte to that commit before writing, and refuse replacement of changed historical outputs. Normal builds use inert checked-in bytes and never fetch Git history or call GitHub. Generated files use deterministic two-space JSON plus one newline; hand-formatting them breaks exact reproduction.

Future source changes need commit A for the source/compatibility edits and commit B for deliberately appended ledger files pinning A. A may be a transitional failing head; final B must pass before merge. `manifest.capture.commit` names source A, not the commit containing its own ledger metadata. Compatibility-only edits may retain the substantive version but still require a new exact raw snapshot/current-source binding. Other substantive or authorship changes append versions and need fresh qualification. Old object hashes, recorded evidence, editions and dissent remain immutable.

The current CLI reproduces the initial capture; it does **not** automatically append arbitrary future editions, assign reviewers, discover new GitHub activity or update a problem. Later records/editions are deliberately authored under the schema and reviewed through GitHub. No unattended polling or publication is implemented.
