Read the [interfaces](REMAINING_RECORDS_RECOVERY_INTERFACES.md), [earlier six-key contract](PROGRAM_RECORD_RECOVERY_PLAN.md) and [writing standard](../STYLE.md). Engineering checks below are not human review, institutional validation or release acceptance.

## Result and exact scope

People can keep using the twenty existing saved desks, recover a corrupt or conflicting copy, retry an exact failed write and restore a reviewed native backup without silently replacing newer work. Every late file read and delayed save is bound to the current selection and form intent. An unfinished editor remains separate from saved records unless that desk's original native format explicitly includes its draft.

The scope is seven narrative research keys, four other local research/publication keys and nine original partner keys. Preserve their keys, native shapes, IDs, record order, original timestamps, raw draft strings, editing identity and unknown-versus-zero semantics. No account, provider, server write, shared approval, new storage key, automatic migration or automatic graph capture is added. The earlier six-key engine and released donor, course, study, artifact, graph, ledger, publication and shared-OS stores keep their separate contracts.

## Native compatibility

Keep original native JSON: two-space indentation for backup downloads, no terminal newline; compact JSON for saved values. The exact observed presence and raw string are the concurrency baseline, even when their original whitespace differs. Native backup, raw saved-copy archive and raw-form archive are distinct formats. Importing one into another must fail. Do not rewrite a native object merely to add recovery metadata.

Admission uses a frozen inert definition table and retains accepted strings and property/array order. It must not call an older validator that fills missing fields, trims values, drops unknown fields or rewrites editing IDs. Inspect a read-only trimmed copy where required for semantic validation; preserve the original accepted string. Unknown fields/versions, duplicate JSON keys, unsupported spellings, unresolved identities and excessive size become protected data with an explanation. They are not silently normalized or deleted. Current producer-canonical v1 data remains compatible; this is not a promise to accept every permissive shape an older predicate accidentally accepted. In particular, the new finite whole-file bound can refuse an otherwise legacy-shaped research object.

Research has at most 200 records. Each is `{id,createdAt,updatedAt,values}`; IDs remain arbitrary nonempty strings up to 100 UTF-16 code units, unique within that desk. Do not strengthen them to a UUID or slug rule. Current producers emit canonical ISO timestamps; retain both timestamps and accept their current canonical form without inventing chronological ordering. A `draft` is a sparse subset of known fields: missing and explicitly empty values remain distinct, and invalid partial numeric/date/URL/select text is permitted within its field length. All saved `values` fields must be present and valid; no extra field disappears. `editing` is null or an existing ID; Replication's frozen versions require null. Forking a frozen row copies its values to a new draft and never edits that saved row in place. The History and Moral comparisons retain distinct first/second IDs; Methods retains its three lower/upper relations. Saved fields, exact choices, defaults and bounds are frozen in the interfaces.

Manuscript remains a partial nine-field draft with a known article type. Nomination packets keep their ten required nonblank fields, known depth phrase, at most 100 unique nonempty IDs of fewer than 100 code units and array order. Depth Census keeps one uppercase three-letter currency, at most 1,000 unique IDs of fewer than 100 code units, exact activity/source strings, amounts 0–1e9 with existing cent precision and depth `unknown` or `0`–`4`. Zero stays measured zero; unclassified stays unclassified. No totals or depth descriptions become organization ratings.

Country notes retain the original bare map and all 217 known code identities. Each present country has exactly `voices`, `institutions` and `gaps`, each a string up to 10,000 code units. Absent country and explicitly empty notes remain distinct. A full-map JSON backup/previewed restore is added because the existing selected-country Markdown brief is not a backup of the other countries. The comparison CSV, source/observation identities, coverage labels, factual projection and country brief remain governed by R1. Do not edit any of the fourteen observation-baseline files. Country/compare fragment choices remain codes only, with no private notes in URLs.

Partner keys retain the complete bare v1 envelope, context, 46 collections and `{id,values}` rows. At most 250 records per collection and 500 total; IDs match `[A-Za-z0-9_-]{1,100}` and are unique across all collections of one partner desk. `updated` remains empty for a blank workspace or a retained parseable timestamp of at most 100 code units. Current saves capture one ISO timestamp; retry never changes it. Text limits remain 500, or 5,000 for textarea. Requiredness, exact choices, real dates and number bounds remain; the existing effective numeric maximum is `min(config.max ?? 1e9,1e9)`, even where an inert descriptor advertises 1e12. `amount` and `budget` retain the existing nonnegative decimal-text rule with at most two fractional places; `minutes` stays an integer. Summit UTC `start` remains `HH:MM`. Optional blank amounts remain unknown, distinct from string `0`. Do not add cross-collection references that the original format did not require. Existing kit/CSV/transparency/calendar calculations and their planning limits remain unchanged.

## Native control hydration

Assigning an admitted string to a native HTML input can sanitize it. An unrelated save, autosave or native export must not rewrite an exact accepted string merely because `type=text/url/number/date` or a textarea changed its displayed value. Keep a detached pair `{original,display}` per adopted control and source/form/editing identity: `original` is the exact admitted string and `display` is the value read immediately after assignment. Original substitution is valid only while that individual field is untouched since adoption. Before handling its first explicit `input` or `change`, permanently invalidate that field’s pair for this adoption, even if its exposed value is unchanged or later returns to the sanitized display. While an untouched field still equals its hydrated display, candidate/native-export reading returns the exact original; otherwise it returns the actual current control string. A user edit followed by a return to the old display must not resurrect the original. Programmatic prefill that represents explicit user intent invalidates the affected fields too. Keep untouched pairs and touched status through failed saves, status refresh and exact Retry; the separately captured failed candidate remains exact and is not rewritten from a newly touched form. Reset this field state only during deliberate adoption; never rebuild it from a stale saved snapshot over an unfinished form.

Use text controls with appropriate `inputmode` for numeric strings when native number sanitization would destroy their representation; schema validation still decides valid records. Research drafts can contain partial invalid number/date/URL strings, so provide controls that can display/edit that text or an equally explicit exact-original preservation path. Do not normalize such a draft into an empty or zero value. The raw-form archive remains different: it records literal exposed `control.value` strings, without substituting a hidden original/display pair. The admitted original remains in native memory and its native snapshot/export. A DOM double cannot establish native sanitization behavior; use bounded actual Chrome acceptance for the named input types, CR/LF and partial draft cases.

## Proposed capacities and measured feasibility

Whole UTF-8 limits include the complete original native object and all formatting. They apply before saved state is assigned and to raw native input, compact saved serialization and pretty native backup. Whichever whole limit is reached first wins over individual field/count limits. Refuse and retain the current key, memory and forms; never truncate or quietly select a subset.

| Native family | Proposed whole limit | Actual valid producer-shaped proof |
| --- | ---: | --- |
| Each research desk | 32,000,000 bytes | All 200 full ordinary Replication records: 24,112,597 bytes. A valid mixed escaped-text export reaches exactly 32,000,000; another schema-valid character reaches 32,000,001 and must be refused by capacity |
| Manuscript | 1,000,000 bytes, existing limit | All maximal text sections with six-byte JSON escapes: 431,278 bytes |
| Nominations | 24,000,000 bytes, existing limit | All 100 maximal escaped packets, including unique 99-code-unit escaped IDs: 23,099,602 bytes |
| Depth Census | 32,000,000 bytes, existing limit | All 1,000 maximal escaped rows, including unique 99-code-unit escaped IDs: 31,918,039 bytes |
| Country notes | 48,000,000 bytes | All 217 known countries, three 10,000-code-unit escaped notes each: 39,075,843 bytes; unchanged actual current reader accepts every code and retains exact saved bytes |
| Each partner desk | 8,000,000 bytes, existing limit | Existing native serializer/producer capacity remains. Tests must retain its reservation for a later 24-character `updated` timestamp when an empty/short timestamp is present |

The 32 MB research limit deliberately replaces the incompatible 2 MB picker limit, rather than claiming every maximum combination fits. Valid 200-record escaped examples range up to 136,112,597 bytes; a loose all-field bound is still larger. Such data must stay protected/refused above 32 MB. Existing saved raw data remains untouched and recoverable within the raw-copy limit. An oversized external file remains with its owner; show a split/copy explanation before reading it. There is no automatic shrink, migration or exceptional oversized write path.

Additional proposed limits: JSON depth 32; raw saved-copy archive 128,000,000 bytes including the escaped wrapper; raw-form archive 1,000,000 bytes including the complete wrapper; local file-read deadline 30 seconds. A 48 MB admitted ASCII native JSON string needs at most 96 MB plus its small wrapper when re-escaped. The actual 39,075,843-byte country native string becomes a 45,590,115-byte raw archive. Malformed raw strings can still exceed 128 MB when escaped: refuse that archive without changing or discarding the original. Preserve original UTF-16 code units, including lone surrogates, in the escaped raw wrapper; read denial does not invent bytes.

The largest partner page has context plus six collection editors: 138,500 declared text code units; a maximal escaped seven-form archive with 100-character editing IDs is 833,624 bytes. The largest research editor declares 136,000 text code units, at most 816,000 escaped value bytes before its bounded wrapper. The 1 MB form archive covers these real declared limits. Number/date/select controls without an explicit HTML maxlength are bounded by the whole archive only; an out-of-contract programmatically oversized DOM value may be refused. Keep that DOM intact and offer a clearly labeled plain-text copy/download of exposed control strings. Number/date controls may conceal invalid internal text; do not claim inaccessible characters are present in a backup, and do not clean or reset such a control because its exposed value is empty. Never clear input because a backup could not be produced.

A separate Node 24.22.1/darwin feasibility run actually parses, clones, serializes, UTF-8 encodes and SHA-256 hashes the same complete values. The exact 32 MB research value completes those steps in about 52 ms; the 39.1 MB country value in about 62 ms on this machine. Process peak RSS is approximately 260 MiB after the research path, 396 MiB after the following country path and 610 MiB after both fixtures, DOM markup and raw archives coexist. This uses native `JSON.parse` and existing producer admission, not the not-yet-built strict duplicate-key scanner. These are measured engineering costs, not browser or low-memory-device performance acceptance. Do not retain the two complete histories, arbitrary jobs or duplicate backups in a real session. Browser acceptance must exercise the complete large-file path without claiming a universal latency or memory guarantee; splitting remains available below the hard bounds.

## Persistence, ownership and pending work

Use a new twenty-key closed facade, with separate inert schema, bounded format and controls modules. Reuse the earlier guarded-copy algorithm where useful; do not extend a released engine's fixed registry or expose generic storage callbacks. All saves and replacements are awaited. A Promise cannot be reported as a saved boolean.

When available, open/read and exact comparison use the exact key under Web Locks; writes require that lock. Missing lock/hash capability is read-only recovery/export. The observed baseline includes absence, not just a parsed value. Compare raw saved strings by exact UTF-16 code units; if a review digest includes corrupt raw data, hash its escaped JSON wrapper rather than lossy UTF-8 replacement encoding. A readable absent key may have a valid unsaved default; read denial, empty raw string, corrupt data, saved empty data and absence stay distinct. Recheck baseline plus captured session/view generation immediately before every write, including no-op, retry, undo, removal and replacement. This coordinates updated clients only; arbitrary direct writes and older cached tabs that ignore locks are not transactional participants. Ask users to reload older open desk tabs in the release notice.

A failed write retains the admitted candidate, exact timestamp, presence operation and previous recovery state. Normal saves refuse while that intent is pending; retry writes that exact candidate only. New typing remains in raw DOM/form state. An explicit reviewed Replace with current draft action can supersede the earlier failed candidate; newer form edits still revoke that permission. An autosave must never overwrite the only failed candidate merely because another input arrived.

All asynchronous full-payload work shares one per-session lane: saves, native restore previews and example/replacement previews, including their preparation, serialization, digest and lock waits. Retain at most one running job and the newest unstarted job across all those kinds, rather than a separate queue per kind. Synchronous `captureSave` still performs complete ownership detachment plus schema/capacity admission before it returns, so a caller knows whether a proposed new row was admitted. Before detaching the newest input, revoke and release any previous unstarted owned capture/preview payload. An opaque capture handle may survive, but its old internal payload/authority must not; a later `saveCaptured` resolves superseded. Capture ownership and a submitted job’s promise are distinct. Replacing a pending submitted save settles it superseded immediately; replacing a pending preview rejects it with typed `superseded` immediately. The running job may finish an already-started digest/lock wait, but revoked authority cannot yield a preview or write. Never start a parallel async full validation/hash pipeline outside the lane. Bound application-owned retained copies, not arbitrary caller references or the browser’s garbage collection. No closure per keystroke or copy/hash pipeline is queued behind a held lock. For autosaved research/manuscript/country fields, capture raw strings synchronously, mark the view dirty immediately and coalesce the latest update using a fixed 250 ms timer. Capture a complete validated owned candidate before queueing; immutable validated record prefixes may be shared inside the engine, but caller references cannot retarget it. Clear the timer and revoke authority at reload/import/cancel/dispose; never lose the most recent raw form because debounce has not fired. Page leaving guards dirty forms, pending timers, failed candidates and meaningful unsaved memory. Download requests do not mark work clean.

All previews, remove reviews and explicit superseding replacements bind one owning session/tracker, key, source bytes/hash, observed presence/raw bytes, current memory identity, source selection, generation and captured discard permission. They are one use. Forged/copied previews fail. Cancel, a new file event including empty/invalid/oversized choices, edit, source/country choice, save, reload, clear, undo, external notice and dispose revoke earlier authority at entry. Apply never reads the file again or invents a new clock value. Corrupt A remains separately exportable when unseen B or C appears; every new B/C requires another explicit review before replacement authority.

Use an abortable browser `FileReader` for owned byte reads, with a 30-second deadline. Abort and detach handlers before a new choice/cancel; generation checks still reject late load/error/abort completion. Do not wrap unbounded concurrent `File.text()` promises and call that a one-read bound. If the required abortable read capability is unavailable, native import is unavailable with an explanation while valid exports/raw recovery remain usable. Tests may inject a controlled constructor-bound read seam outside engine locks. No read/UI callback is accepted by later engine commands.

Clear is a reviewed removal of that one key, not a saved empty sentinel. Empty saved value and removed value remain distinct. Keep one owned Undo with previous valid value and presence. Failed set/remove/undo retains useful recovery and exact retry; reload adopts only a successfully read/admitted value or proven absence. Failed reload preserves current memory, failed intent, raw forms and protected A. Notifications are constructor-bound, immutable status/adoption messages after locks release; they cannot authorize writes, and notification failure cannot change a completed write's outcome.

## Caller integration and export meaning

Research preserves `research:change`, `research:state`, `research:prefill` and `research:inspect` as outside-lock notifications/input events. Calculations consume live raw draft fields where they already do so; saved-record lists consume admitted current records. Prefill is explicit local form intent and revokes import authority; it does not confer source review. The Methods/Replication artifact companion and Evidence Study register remain separate, and their selected legacy-file adapters keep their own declared limits.

For Research, native JSON and Markdown retain the current unfinished `draft` when it is within the native draft schema, including its invalid partial strings and current editing ID. Building that export is a read-only explicit overlay of the current form onto an owned snapshot; it does not save or mark the form clean. Saved CSV remains saved records only. Manuscript's existing form JSON likewise exports the current partial form without claiming it persisted. If a live form cannot fit the native schema, retain it and offer raw-form recovery instead. Nomination/Depth/partner JSON and generated kits contain current admitted records, not unsaved editor fields. Their raw-form download is separately labeled. Country full JSON includes every current note and may explicitly overlay the current primary-country form; its single-country brief remains a selected output, not a whole-map backup.

Only a successful saved/no-op result with the exact still-current token may clean that submitted form or reset/close its editor. Failure, supersession or a newer edit retains it. Do not clear unrelated forms after a context/row save. Post-retry status can rerender admitted saved records and calculations but must retain every unfinished field. Exports from a failed in-memory candidate disclose that persistence state. Say a download was requested; native file-save acceptance is a separate check.

For a new Nomination, Depth activity or partner row, allocate one proposed ID on submit, build the complete candidate and call synchronous `captureSave`. If pre-admission validation/capacity refusal throws, do not install that proposed new ID as an editor target. After successful admission, bind the captured ID to that exact key, collection and unfinished editor before awaiting persistence. Retain it through an admitted failure, later typing and exact Retry; do not regenerate it on resubmit. A later submit updates the same admitted row, or explicitly inserts that same admitted-new identity if it has not yet entered the current model. Distinguish an admitted-new identity from editing a preexisting row that has disappeared, which must not be silently recreated. A failed new row → edit → Retry → resubmit must yield one row with the same ID. Clear the binding only through explicit New/Cancel or a successful still-current editor reset/deliberate adoption. A stale completion cannot restore a cleared binding, and another collection/source’s matching ID is not the same editing target. Pending failed candidate bytes remain separate from newer raw fields and their editor identity.

Country comparison/search/filter changes cannot refill or discard the primary-country note editor. Changing the primary country or using an Open button first resolves that captured form/timer/failed intent, or requests explicit discard for exactly that version; a later edit invalidates the decision. Keep the prior primary-country identity during the await and revert a stale selector without replacing newer notes. Compare-only changes preserve note text. Do not copy notes into factual APIs, public snapshots or URLs.

Partner context and up to six simultaneous collection editors remain separate forms. Saving one does not adopt another. Load-example, import, Clear, Undo and reload require their own current reviewed discard authority. Existing kit/CSV export excludes partial forms and filters no saved records; Fund's selected transparency packet and Summit's tentative UTC calendar keep their exact selection and planning disclaimers. The graph companion can observe an explicit updated partner value through its existing copy flow; no synchronization or authority is added.

Private forms remain default-disabled in server HTML and intercepted before asynchronous startup. New recovery controls must not weaken the separately tested no-JavaScript/default-GET privacy correction. Text renders as text; source links follow the existing safe URL rules. No form draft is executed as HTML, Markdown or script.

## Accepted raw-byte transport refinement

Root accepted a narrow implementation refinement after the original freeze: a genuine ordinary fixed ArrayBuffer-backed Uint8Array with the exact native prototype transports only its indexed bytes. Unrelated own properties are ignored and never invoked, copied or treated as authority. Enumerating every own byte-index property at 32–48 MB would itself create an excessive property-name inventory. Intrinsic view/buffer getters and native destination allocation plus Uint8Array set must reject proxy, subclass, shared, resizable or detached substitutes without looking up a source constructor, species, iterator or custom method. Native object/schema admission still rejects accessors and decorated structures. Adversarial throwing decorations and complete large-byte inputs require explicit tests; this changes no key or model authority.
