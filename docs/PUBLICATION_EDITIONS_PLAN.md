## Immutable source and artifact design

Store file-per-object source snapshots and edition manifests in `src/data/publication-editions/`. Each allowlisted source snapshot retains exact inert UTF-8, committed path/ref and raw SHA-256. Its enclosing object has a separate hash. A versioned adapter verifies source projections, member order and every field used by a count. Unknown source fields need explicit classification; they are not silently dropped.

Use the same two-commit discipline as R4: source/method changes first in A; deliberately captured registry/artifacts in B pin A. If R4-covered bytes change, complete their source/ledger workflow before R5 pins that closed ledger. Do not create a cycle between a publication, its supporting ledger edition and their commits. Normal builds read checked-in snapshots and never fetch history, use the current clock or call a provider.

An edition core has a canonical content hash. Text artifacts may contain this core hash and edition ID. Their byte hashes then enter the final edition manifest hash. They must not contain that enclosing manifest hash: doing so would create a cycle. The edition JSON is the manifest, not an artifact that hashes its own download bytes. Registry hash covers sorted edition/source pins; editions never depend on a future registry root. New server mail artifacts are downstream bindings to a completed public edition hash, not upstream dependencies of that same edition.

Corrections append a new ID/sequence with a reason and supersedes reference. Prior IDs, core/manifests, snapshots and artifacts cannot be changed or removed by an ordinary PR. A mandatory Node/Git checker compares the complete public and service mail history with an exact available committed base, including every old referenced blob. PR CI binds the trusted PR base/head; release binds the exact previous accepted/push base and release head. Missing base objects/closure fail CI/release rather than skipping append-only checks. Only local offline mode may report append-only unavailable while still checking current closure; that is not release acceptance. The initial bootstrap proves both reserved roots absent at a real committed base. The interfaces define the exact workflow and gate API; the checker itself never fetches. This is repository policy, not a claim that a privileged repository owner cannot rewrite history.

All five initial editions use an explicit editorial-draft label. Member qualifications are exact R4 references, not a whole-edition endorsement. Neither freezing an edition nor an email acknowledgement upgrades source or peer review. Future whole-edition reviewed wording needs a deliberately registered exact-subject R4 adapter and actual eligible human statements; this slice supplies neither by inference.

## Private proposal desk and recovery

Add one opt-in local key/lock, `charitology.publication-editions.v1`, using the exact owned prepare/commit/recovery store interfaces. The final L1 corruption safeguard applies: preserve original corrupt A separately from newly observed B/C, refuse the first unseen replacement and require a fresh explicit review. No already-blocked exemption may hide newer storage bytes. It does not read, migrate or write old manuscript/notebook/study/artifact/program keys, shared OS data or subscriber state.

Server capture validates the closed R4 projection with the existing Node-only research implementation. The browser neither bundles that reducer nor duplicates research qualification. It checks strict schemas, hashes and complete source/member closure against the server's fixed public catalog. The initial page contains small identity/size/hash offers; an explicit selection fetches only its known bounded same-origin basis bundle. All retained basis/source bytes remain complete, with no all-edition payload on every page.

The browser explicitly captures offered fixed public edition manifests with their exact source closure, then selects members by edition ID plus member ID/hash. One proposal version may pin up to five editions; shared source copies are deduplicated without changing them. It records a proposed title/summary and source-linked authored blocks, and freezes self-recorded local proposal versions. It can compare its exact stored basis with a newer offered capture, retaining the old one. No proposal writes repository files or creates a sendable issue. A selected proposal packet is downloaded for manual redaction and a GitHub PR; publication occurs only after normal source capture/review/checks.

The complete JSON backup contains all local proposals, versions, selected source copies, operator notes and raw unfinished form, including unselected work. Warn before download. A selected Markdown/JSON proposal packet contains the chosen version's selected members plus its full pinned public manifests/source closure and explicit omissions. It labels any unselected public proof/context inside those manifests, excludes unrelated private drafts/notes and says **draft proposal, not published or independently reviewed**. It is not a full restore backup. Private editorial notes are never automatically copied into a public edition or mail artifact.

Require Web Locks plus exact observed saved bytes and a separate current-memory hash. No initial write, lock-free fallback, background discovery or automatic upload. Guard prepare/commit/undo/reload/restore/clear and snapshot all inputs before awaits. Corrupt readable bytes remain downloadable; denied storage is unavailable, not blank. Quota failure keeps a valid exportable candidate and visible unsaved warning; retry persists that exact candidate without replaying a command. Foreign writes before or after preview block replacement until explicit recovery. Raw forms can be downloaded separately when the complete backup cannot hold them. Failed/no-op commands never discard them.

## Explicit issue delivery on the existing service

Retain `content.mjs::edition` and the unqualified existing admin preview/campaign routes as **Edition 1 aliases forever**. Add explicit allowlisted issue routes and immutable generated mail artifacts within the service root. Never accept request HTML, recipients, arbitrary URLs, paths, `latest` aliases or issue uploads. No new provider, Topic, Segment, purchase, credential scope, marketing purpose or automatic audience subscription is proposed.

The operational journey is: select immutable issue → inspect exact public content and mail preview → acknowledge the prepare proof → create one native unsent draft → inspect a fresh send preview → acknowledge its exact native/content/audience binding → deliberately request one send. Fifteen-minute proofs are authenticated **operational acknowledgements under a shared bearer**, not named human peer review. The Letter may remain an honestly labeled editorial draft. Source/scientific claims retain their separate R4 gates.

Intended recipients are only current confirmed local subscribers whose exact native Segment membership matches. Proofs bind a private keyed digest of normalized intended addresses and consent generations plus a count; new subscribers, withdrawal, pending resync, native membership or transport drift invalidate the proof. No recipient list is returned to a public page or stored in proposal backups. Re-read current readiness, tracking-off state, exact intended set and native draft fields before the send checkpoint. Do not mutate consent to make this comparison pass.

Native Broadcast addresses its Segment at provider send/processing time; this application cannot atomically freeze another dashboard's membership/Topic changes. Its lock coordinates this application only. Local checks and purpose-specific consent do not authorize an arbitrary current Segment. Native preferences/global unsubscribe/suppression remain the final delivery filter, including changes after the last check. There is no transactional-email bypass, global flag reset or claim that the preview count is a delivered count.

Lost create/send response or failed finalization leaves creating/create_unknown/sending/send_unknown stopped indefinitely. No automatic retry, time-based reset, new-key escape, provider-list adoption or delete/reset endpoint exists. A corrected publication is not a retry mechanism for an uncertain prior mail. A closed, hashed service-root Letter lineage pins exact public ancestors, including non-mailed intermediate editions. The gateway resolves it without remote fetches and blocks a genuinely new attempt if any mailed ancestor has an uncertain creating/sending state. Missing/cyclic/mismatched lineage fails rather than silently dropping that stop. A successful response from the original proof/operation-bound in-flight create may finalize creating to draft once; this permitted finalization is explicitly distinct from forbidden reset/reconcile recovery.

Unknown create without a provider ID stays unresolved pending private operational investigation. Provider accepted, provider reports sent, receiving-server delivery and human reading remain different facts. No new newsletter delivery callback aggregate is required; preserve the existing signed withdrawal/OS feedback path and atomic deduplication. ## Bounds and migration

Recommended first bounds are fixed in the interfaces: 100 public editions, 1,000 shared source snapshots, 1,000 member/source pins per edition, 2 MiB per complete pretty manifest/text artifact, 20 MiB total checked-in registry/snapshot/artifact bytes; 20 local proposals/100 versions and a 2 MiB complete local backup. A genuine oversized book requires a deliberately reviewed new artifact design, never truncation or deletion of prior editions.

Keep at most 20 unexpired unconsumed operational proofs and 2 MiB actual proof rows; retain a proof referenced by a campaign and minimal campaign/attempt/unknown tombstones indefinitely. At most 100 campaigns, bound to registered IDs; reserve bounded finalization space before provider mutation. No unbounded new event log is needed. Expired unreferenced proofs may be cleaned; cleanup never clears campaign identity, consent/suppression or OS intents and never sends.

An idempotent additive migration preserves populated accepted/unknown legacy rows. New fields are nullable where legacy evidence is absent. Do not backfill accepted/attempt times from `updated_at`, invent an old review proof, or recanonicalize Edition 1's hash. Privately inventory actual states first; unsupported history fails preflight. SQL immutability/transition guards and application tests prevent ordinary identity reset. A database owner retains powers outside that application guarantee.
