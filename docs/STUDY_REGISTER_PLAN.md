# Study register: frozen R2 implementation plan

Frozen before implementation · October 26, 2026 · review: draft · AI-assisted source/code inspection. This plan authorizes no external search, provider, account or independent-review claim. The exact interfaces in [STUDY_REGISTER_INTERFACES.md](STUDY_REGISTER_INTERFACES.md) govern where an earlier illustrative proposal differs.

## Intended outcome

Complete one browser-local question-to-screening workflow: freeze a protocol, preview/import citation records, resolve duplicates, tag the resulting reports, record two labeled screening decisions, reconcile disagreement, and export traceable included reports, exclusion reasons and exact flow counts. Connect that register to the Evidence Library and Evidence Reviews without changing the public evidence labels of their sources.

This is a register of sources and user-recorded research work. It does not run literature searches, verify papers or reviewer identities, provide independent preregistration, perform meta-analysis, rank charities or establish that a systematic review occurred. No real study results or reviewer activity are seeded. Existing public citations remain citations until a person classifies them; a cited organization homepage, report, method guide or discussion is not automatically an empirical study.

Recommended first slice: static public bibliography plus one private local register per browser, shared between its Library and Reviews views. No backend, accounts, paid service, external metadata API, DOI lookup, network proxy or new OS permission surface. A later shared-review system would need its own identity, access and immutable-review contract; two labels in local storage cannot supply those guarantees.

## What is present now

- `src/lib/sources.ts::allCitations()` builds title/URL/publisher/year/backlinks from content collections and other public data. Its URL-only deduplication is a bibliography convenience. It removes trailing slashes and rewrites HTTP to HTTPS; those broad transformations must not silently become new register equivalence rules.
- `src/components/record/evidence-library.astro` renders the sorted bibliography and citing-page links. It has no dedicated search/filter or study screening interface.
- `src/components/programs/evidence-reviews.astro` combines the 15-entry draft intervention catalog with `ResearchWorkspace.astro`. Each saved extraction repeats question/search/inclusion fields and has a source, design and narrative effect/bias/synthesis notes. It has no structured imported queue, immutable protocol relationship, duplicate ledger, two-lane decisions or computed flow totals. Its free-text selection count is user prose, not derived counts.
- `src/lib/client/research-programs.ts` currently bounds records at 200, validates its version 1 program format, previews JSON replacement and supports exports/undo. Its exact persisted key for this desk is `charitology.research-program.evidence-reviews.v1`. `researchStorage()` uses `guardedDraft`; unreadable data blocks saving and stale tabs cannot overwrite saved bytes. These files and old keys must remain intact.
- `durable-store.ts` offers the stronger recovery pattern: retain raw stored bytes and unsaved work, validate backups, preview explicit replacement against the exact observed saved value, and expose recovery controls. It prepends `charitology.` internally. A new adapter must use its real final key, not accidentally apply the prefix twice.
- `dom.ts`, `files.ts` and `markdown.ts` supply safe rendering/download/Markdown primitives. CSV needs explicit spreadsheet-formula protection in the new register export; quoting by itself is not that protection.

## Scope choices recommended for the first slice

| Choice | Recommendation and tradeoff |
| --- | --- |
| Persistence | One namespaced browser workspace, complete portable JSON. No shared-review or authenticated-person claim. |
| Citation import | Mapped UTF-8 CSV and the register's versioned JSON backup. Add a small documented citation-JSON format only if useful. Defer RIS/BibTeX/XML parsing until their exact dialects and error contracts are separately scoped; do not guess compatibility from file extensions. |
| Existing bibliography | Explicitly select public citations to add. Preserve their citing-page backlinks and mark classification unknown. Browsing/searching the public list does not import it or count as screening. |
| Deduplication | Suggest DOI/PMID/exact safe-URL matches, but show every proposed cluster before commit. Title/year similarity is a suggestion only. Never silently combine conflicting identifiers or different reports of one study. |
| Reviewers | Two local labels, initially `Reviewer A` and `Reviewer B`; every decision says self-recorded. Both can be entered by the same person. No identity verification, credential, peer-review badge or assertion of independent review. |
| Screening | Two stages: title/abstract, then full report. Each stage has A/B decisions and a reasoned resolution when they disagree. Unknown/undecided is distinct from exclusion. |
| Protocol | Immutable local versions with exact content hash. All active screening/extraction records bind to one selected version and citation revision. A changed protocol starts unassessed work for that version; no silent carry-forward. |
| Synthesis | Export included-report metadata and optional structured extraction inputs. No pooled estimate, ranking, certainty grade or conclusion generated by the software. |
| Publication | Nothing is submitted or published automatically. Public content stays draft; local decisions cannot update Astro `review` or intervention evidence fields. |

Recommended limits, enforced through count **and** byte admission: 1,000 total retained report identities, including retired merge sources, 2,000 imported occurrences, 20 import batches, 20 frozen protocol versions, 8,000 bounded decision/history entries, 25 visible rows/page, 1 MiB per citation CSV and 2 MiB per complete backup/workspace. No field or row is truncated to fit. The actual pretty-printed backup envelope, draft and eventual timestamp must fit the same 2 MiB limit before accepting a mutation, so an exported backup is always importable. Browser quota is shared with other tools: a quota failure still preserves an exportable in-memory workspace and a visible unsaved warning. These are initial product bounds, not claims about systematic-review completeness.

## User journey and UI

1. **Browse sources.** The Evidence Library gains explicit title/publisher/year/source-URL/backlink search and filters. Unknown year is a separate state. Select sources to preview adding to a local register; never label all search hits studies. The full bibliography stays readable without JavaScript.
2. **Define the question.** In the register, enter title, population/setting, intervention/comparison, outcomes/time horizon, eligible designs/source types, inclusion/exclusion rules and planned search sources/strings. Freeze a local version after a review screen. Show its version/hash and the notice that local time is not independent registration. Record actual searches separately; a planned query is not a search performed.
3. **Import a search result file.** Choose CSV, map columns, enter its actual source/query/date if known, and inspect the preview. Show raw row count, valid/malformed rows, unmapped columns, possible duplicate clusters, proposed normalized IDs and post-commit capacity. Require explicit commit against the unchanged workspace hash. One invalid row blocks the whole commit by default; download its diagnostics and correct the file. Do not quietly skip malformed rows. Missing date/query is allowed as unknown and visibly weakens search provenance.
4. **Resolve duplicates.** Compare candidates with all original rows and provenance visible. Pick a canonical report or decline the suggested match. Preserve alternative metadata and occurrence links. A conflicting DOI/PMID must be resolved deliberately, never overwritten. Splitting a mistaken cluster restores its members and invalidates affected screening as needed. Do not equate multiple articles about the same underlying study with duplicate articles.
5. **Tag and describe.** Source classification starts unknown. Optional metadata includes design, population/setting, intervention/cause IDs, outcomes, publication year, published author strings, user summary, source/table references . Keep user descriptions separate from imported metadata. Do not infer design, population, effect or evidence grade from a title. Missing values remain null/unknown.
6. **Screen one stage.** Choose a lane and record include/advance, exclude or undecided, with a required reason for exclusion. Explicitly disclose that the lane label is not an authenticated reviewer. Decisions bind protocol hash, citation revision and stage. Matching completed A/B decisions derive recorded agreement. A conflict remains unresolved until the person records a resolver label, chosen outcome and explanation; that still is a self-recorded resolution, not independent verification.
7. **Obtain and screen the full report.** A title/abstract advance is not inclusion. Mark full report pending, obtained or not retrieved, with a reason for not retrieved. Full-report decisions require obtained state and the two-lane process. A not-retrieved report does not become an excluded or zero-effect study. Final exclusion keeps its stage, reason and provenance.
8. **Extract included-report inputs.** The new register can hold a small optional extraction tied to that included report/protocol: comparison, population, outcome/measure, unit, follow-up, reported estimate/interval, denominator if applicable, source page/table and bias/limitations. Estimate/limits/denominator can be null; explicit numeric zero stays zero. No estimate is necessary for qualitative work. Numbers are user-entered, not checked empirical findings. The existing narrative extraction desk remains usable and unchanged. A future prefill bridge requires a separate dirty-form/provenance contract and is deferred.
9. **Inspect flow and export.** Show protocol version, pending/conflicting work and exact record/report counts. Export full JSON, separate metadata/occurrence/decision/exclusion/extraction CSVs and a source-linked Markdown memo containing labels and limitations. A frozen export packet records the current input hash, counts and protocol; later edits never relabel that packet's earlier state.
10. **Reload or recover.** Saved data returns on both views. A stale/corrupt/failed-save notice persists until resolved. Offer current-work backup, raw saved-byte recovery, explicit re-read and previewed validated restore. Undo is a guarded new mutation; loading another saved workspace clears the old undo stack. Clear requires a review/confirmation and affects only this key.

Pagination/filtering changes only the view, never the data or flow denominators. Before moving a dirty form, show keep/edit/discard choices; a failed save must not silently clear its values. A selected report should remain selected after a filter change where possible, with a clear notice when hidden. Do not render thousands of full notes into the DOM.

## Proposed data and invariants

The version 1 JSON envelope is `{format:"charitology-study-register",version:1,exportedAt,checksum,workspace}`. The checksum covers a deterministic canonical workspace, excluding `exportedAt` and the checksum itself. It detects changed bytes/content; it does not verify identity, source truth, chronology or independent registration.

Suggested workspace entities:

- `protocols`: immutable ID/version/hash/content/local frozen time, plus one selected protocol ID. Search plans belong here. Forking creates a new version; it never edits a prior one.
- `searchRuns`: recorded source, exact query, date/time or unknown, source file hash and a user-supplied provenance note. A file import alone does not prove that the search ran or was comprehensive.
- `imports`: stable ID, search-run reference, file hash/format/column map and bounded source rows with row numbers. An exact same file plus same provenance is an idempotent import. A genuinely different run can have identical results and remains distinct. No whole workspace overwrite occurs for a citation-file import.
- `occurrences`: immutable source-row ID, batch/row reference, original citation fields and current canonical report reference. Keep unmapped source values private in the backup; only mapped citation fields enter active metadata. Explicitly warn against importing beneficiary/private case data. Enforce bounds on every retained field rather than truncating it.
- `reports`: stable ID, metadata revision, original and normalized identifiers, canonical metadata, tags/summary and source-occurrence links. Metadata correction retains previous values/history and invalidates decisions for the affected revision. A canonical DOI match is a duplicate proposal, not proof of existence or a verified study.
- `duplicateActions`: accepted/declined merge or split, affected occurrence/report IDs, explanation, local time and before/after references. No deletion of the source rows; unique report counts derive from the current committed mapping.
- `decisions`: immutable local ID, protocol hash, report ID/revision, stage, lane A/B, outcome, reason, local time and supersedes reference. Only the latest unsuperseded decision for that exact binding counts. Reasons use a bounded code plus text; duplicate removal is handled by dedup, not counted again as screening exclusion.
- `resolutions`: exact paired decision IDs, selected outcome, resolver label, explanation and local time. Matching pairs need no dispute resolution. Any changed lane decision invalidates the previous resolution instead of silently applying it to the new pair.
- `retrievals` and `extractions`: report/protocol binding, explicit unknowns and source references. Manual study grouping is deferred; this release counts reports rather than unique studies.
- `draft`, `savedPackets` and bounded history: current unsubmitted controls plus immutable packet input hashes/counts. Preserve history needed to explain current states; reject a new operation at the bound and offer an archive rather than pruning silently.

Every reference must resolve. IDs are unique opaque strings, dates are real calendar dates/canonical instants or explicit unknown, ordinals are nonnegative integers, tags are bounded and unknown enums/fields in the canonical format are rejected. Use safe own-property handling for imported column names; never assign untrusted `__proto__`/constructor keys into ordinary objects. Parse HTML-looking content as text. External URLs are explicit HTTPS references with no credentials; no automatic fetching or execution occurs.

Protocol/citation changes must not mutate past saved packets. For active screening, a former decision for another protocol or citation revision is history, not a current include. An optional later carry-forward feature would need an explicit reviewed reapplication; it is not in this first slice. A user can export old-version decisions without counting them under the new protocol.

## Exact counts without a false systematic-review claim

Count imported **occurrences**, canonical **reports** and manually linked **studies** separately. One report is not automatically one independent study. Call this a screening-flow table; do not claim a completed PRISMA process or a literature search performed by the tool.

For the selected protocol and current report revisions:

- `I` = committed imported occurrences; `D` = occurrences collapsed beyond one per committed canonical report; `U` = canonical reports represented by those occurrences. Require `I = D + U`.
- Title/abstract report states partition `U` into recorded excluded `E1`, advanced `A1` and pending/conflicting `P1`. Require `U = E1 + A1 + P1`.
- Advanced reports partition into final included `N`, full-report excluded `E2`, explicitly not retrieved `NR` and pending/conflicting retrieval/full-report decisions `P2`. Require `A1 = N + E2 + NR + P2`.
- Pending/conflict subtotals are visible inside `P1/P2`, not additional additive flow categories. Partial single-lane decisions remain pending. A recorded exclusion needs its stage/reason; missing values do not become zero effects or exclusions.
- Included-report count is `N`. Manual study grouping is deferred. Never label `N` unique studies or an empirical sample size.

Tests must prove conservation after import/merge/split, a protocol fork, metadata correction, changed decisions, disagreement resolution and undo. Display the literal zero for a genuinely empty category; use unknown only for missing provenance or estimates, not for a derived exact empty count.

## Persistence, export and recovery contract

Prefer a new small typed adapter around the existing `durableCell` rather than adding special cases to the seven-program research engine. Register the validator before mounting the UI. Use logical key `study-register.v1`, making the final storage key exactly `charitology.study-register.v1`; test that actual key with two writers.

- Validate the complete candidate and exact future backup bytes before state replacement. File parsing and asynchronous hashing must carry an operation generation plus expected workspace hash; stale previews or late reads cannot apply after intervening edits.
- Never initialize blank persistent state over unreadable/corrupt saved bytes. Expose the raw saved copy and allow useful in-memory work/export while save remains blocked. Do not claim a raw corrupt export is a valid backup.
- Every create/edit/merge/split/screen/resolve/import/undo/clear path goes through the same guard. Storage events invalidate saving; an explicit reload re-reads and clears unrelated undo. Restore compares the exact raw storage value observed during its preview.
- Quota/read/write failures leave an exportable current draft and unsaved indicator, including dirty controls not yet submitted. Reload/reset/import/close must not discard that work without an explicit action. No silent retry or blank reset.
- Complete JSON is the recovery format. CSV is a flattened analysis/interchange view and must not be called a complete backup. Defuse spreadsheet formulas in CSV while preserving exact original values in JSON. Markdown uses safe text/URL rendering. Export never posts private workspace data or creates a public review.

## Meaningful acceptance checks

1. Import a clearly synthetic CSV containing an exact-ID duplicate, a similar-title distinct report, an organization homepage, missing year, an explicit zero extraction and quoted commas/newlines/BOM. Preview shows every row, retained unknown fields, proposed merges and capacity without changing state. Invalid UTF-8, malformed quote, extra oversized field or bad mapped URL blocks commit; no row silently disappears.
2. Exact same file/provenance reimport is idempotent. Different recorded search run remains distinct in occurrence counts. DOI/PMID conflicts require manual resolution; title similarity never merges automatically. Merge/split preserves all source rows and flow equations.
3. Freeze protocol 1; record A/B agreement and disagreement; resolve with reason. Exclusions retain exact stage/reasons; one lane or unresolved conflict never appears included. Changing either decision invalidates the resolution. There is no independent-review label anywhere.
4. Advance one report but mark it not retrieved; another reaches final inclusion; one is full-report excluded. All count partitions reconcile and never confuse report count with sample size or distinct studies. No report count becomes a sample size or pooled effect.
5. Fork protocol 2 or edit a citation revision: protocol 1 packets remain exact, current decisions return to pending, exports identify both bindings and no prior include leaks into new counts. No browser timestamp is described as independent registration.
6. Unknown estimate/year/denominator stay null; zero stays zero; lower/upper ranges and source references validate. Incomparable units can be exported as distinct inputs but never pooled. No included paper automatically receives a high certainty label or charity rating.
7. A valid backup at the exact byte limit exports and imports successfully; one byte/count over is rejected without mutation. Wrapper timestamps, UTF-8 characters and pretty printing are included. Round-trip all entities, unresolved decisions, source rows and current dirty form values.
8. Two writers on the **actual final key**: stale edits, delete, merge, import, undo and clear cannot replace a newer saved copy. A preview raced by another tab fails on commit. Corrupt JSON, unreadable storage and quota failure preserve raw bytes/current draft and a visible warning; explicit reload clears the unrelated undo snapshot.
9. CSV formula payloads, HTML-looking titles, reserved prototype keys and credential-bearing URLs remain inert/rejected as specified. JSON retains source data exactly; CSV's spreadsheet-safe representation is visibly documented.
10. Real browser proof with synthetic records only: keyboard import/column mapping/commit; page/filter; A/B conflict and resolution; protocol switch; export/reload/restore; corrupt/stale recovery; narrow screen without hidden controls. Inspect downloaded JSON/CSV bytes where the browser tool supports it and record any download-event limitation honestly. No fabricated study search, independent human review or empirical result is used as acceptance evidence.

### Atomic local mutations and recovery

Acquire an exclusive per-origin Web Lock for **every** new-key mutation: save, import commit, metadata correction, merge/split, decision/resolution, protocol fork/switch, undo, restore and clear. Inside that short lock, compare the exact observed saved bytes, validate the candidate and exact backup size, then persist. Do not hold a lock across a user prompt or file parsing. Asynchronous file/hash work produces a preview bound to both a generation and expected workspace hash; recompute/recheck before the locked commit. The exact observed-byte check is still required: a stale editor should refuse, not merge over unseen changes merely because it acquired the lock later.

If Web Locks or required secure-context hashing is unavailable, show the catalog and already readable/exportable work in a visibly read-only mode; do not pretend optimistic localStorage compare/write is race-free. This capability choice must be explained and browser-tested before freeze. A storage event blocks writes and keeps the current dirty draft available for export. Explicit reload creates a fresh adapter and clears old undo; restore/clear use inline accessible review/confirm controls, not native modal dialogs. Failed persistence retains the valid in-memory candidate and visible unsaved state. The exported complete backup must remain importable at its exact byte bound, including its timestamp and wrapper.

### Commands and counted states

Freeze protocol → preview/import source batch → resolve merge/split → correct/tag report → record title/abstract A/B → resolve disagreement → record retrieval → record full-report A/B → resolve disagreement → enter optional extraction → freeze/export packet. Every operation receives expected workspace hash, explicit ID/time and payload; it either returns a fully valid next state or changes nothing. Imported file identity includes exact file bytes, parser/mapping version, column mapping and recorded search provenance; exact replay has no new occurrences. A different run is an explicit different provenance record even when its source bytes match.

A local screening record's identity is protocol content hash + report ID/current metadata revision + stage + lane. A resolution binds the exact two decision IDs; a superseding lane decision invalidates it. A metadata correction or merge/split increments affected report revisions, so old decisions become historical rather than silently carried forward. A protocol fork creates wholly unassessed current work. No automatic carry-forward. Every historical reference resolves to a retained version/tombstone even after a merge/split.

Flow denominators include all committed source occurrences, with batch kind shown (`site-bibliography`, `citation-csv`, or explicit manual record if later authorized). Never call the combined occurrence count “database search results.” For the selected protocol, the three conservation equations above must hold exactly; filtering/paging never changes them. Nonstudy sources can be deliberately excluded with a reason. An obtained full text plus two recorded include decisions/resolution creates **included report**, not independently reviewed study. Manual study grouping is deferred.

### Future migration risks to keep explicit

1. **Local is not a team authority system.** Future OS/shared research import must create unapproved drafts. Local lane names, browser clocks, checksums and “included” decisions never become Better Auth identities, immutable public registration or independent approval. No grant/member/role is imported.
2. **Two identifier domains.** Public bibliography keys, local report/occurrence IDs, DOI/PMID, underlying study groups and future R4 public claim/version IDs represent different things. Preserve mappings and original values; do not join them by title, URL simplification or email. A later publication packet is deliberate and reviewed.
3. **Origin migration and export compatibility.** `charitology.org`, GitHub Pages and development origins have separate stores. Keep version 1 backups readable and the existing extraction key untouched; future versions need explicit reversible previewed migration rather than a silent reset. Never silently adopt old narrative selection prose as counted screening events.
4. **Public provenance is a separate slice.** R4 may later accept a manually proposed, redacted source/claim packet through GitHub, with real evidence and human review links. No local event is automatically appended to R4, no R4 review is fabricated, and public drafts/problem statuses remain unchanged by this register.
5. **Resource/privacy limits.** This is one bounded 2 MiB browser workspace, not an unlimited research archive, copyright permission system or place for beneficiary case histories. Abstracts, notes and raw import columns can contain private/licensed text; explain that exports are local and require deliberate review before sharing. No telemetry, provider fetch, hidden network synchronization or retention/deletion promise is introduced.
