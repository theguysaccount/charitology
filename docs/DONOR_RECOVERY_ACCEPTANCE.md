Duplicate saved IDs are protected/refused. ## Save and recovery boundary

Application mutations use an owned asynchronous facade and the exact full-key Web Lock. Candidates are detached before awaiting, view generations are checked at commit and late completion cannot reset newer form input. Failed writes retain their exact candidate or removal intent for retry/export. Saving an absent default really attempts persistence; only an already persisted equal value may report a no-op.

Web Locks serialize cooperating updated clients. Exact baseline checks refuse observed external changes. They cannot provide localStorage compare-and-swap against older cached clients or direct writers that ignore the lock. Reload older open tool tabs after this release. Unsupported locking/hashing leaves readable records and calculations available with saving explicitly unavailable.

File selection immediately revokes earlier authority. Owned bytes, fatal UTF-8, duplicate-key/depth checks, a 30-second read deadline, one-use private previews and form/recovery generations protect the explicit Apply action. Original protected A and latest observed B/C remain separate lossless raw exports. A new foreign baseline first warns and refuses preview; it is not silently adopted. New form input revokes an earlier discard permission. A download request proves generated bytes, not native file saving.

Normal individual v1 backups retain the old pretty serializer with **no terminal newline** and a complete **8,000,000-byte** cap. Grant bundle input has a complete **24,008,192-byte** cap and each value member also meets its individual cap. The actual grant input boundary test uses a valid complete bundle plus whitespace padding; it does not claim that the fixed nine-weight member can itself produce an eight-MB canonical value. Raw saved-copy wrappers have a separate **64,000,000-byte** cap, preserve UTF-16 code units and remain inert recovery material. Every limit refuses as a whole; no truncation or silent field dropping occurs.

Generic backups contain validated current records, including failed-memory values, rather than every unfinished DOM field. Native CSV/PNG/print/memo outputs have their own smaller scope. A calculation in the cost-model kit enters its saved library only through explicit Save. Measurement warns for pending delayed input; asynchronous unload cannot promise the last write completes.

## Three-key grant workspace

The closed coordinator owns proposals, weights and draft. Relationship operations hold all three locks in lexical draft → proposals → weights order. Writes occur in library → weights → draft order. Private internal leases avoid reacquiring a held lock; no public under-lock callback exists.

Ordinary Save validates the complete requested write set first, stops at the first failed member and retains unattempted candidates. Current-vector export and full intended-vector export are separate, labeled actions. The intended export includes unattempted source members marked unsaved-memory; downloading it grants no authority to apply them.

A complete bundle restore requires a separate preview and confirmation for each member. An intermediate draft/library mismatch is visibly partial, blocks the ordinary editor and preserves exact IDs. Exact-step retry never advances to a later unconfirmed member. The complete success message requires the final fresh locked vector comparison. An initially inconsistent workspace can repair from a valid complete source or explicitly remove the orphan draft. A single-member recovery never claims full-bundle restoration. There is no atomic transaction, hidden journal, automatic rollback or automatic restart resume.
