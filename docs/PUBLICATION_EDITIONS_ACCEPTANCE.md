## What the software checks

The [server model](../src/lib/publication-editions-model.mjs) validates the exact five-family schema, source and member closure, method pins, canonical hashes, ordered members, immutable manifests and rendered artifacts. Exact raw source hashes remain distinct from source-object, core, artifact and manifest hashes. Text artifacts bind the core hash; the enclosing manifest then binds their bytes. An artifact never contains the enclosing manifest hash it helps determine. The [inert method definitions](../src/data/publication-edition-methods.json) record interpretation without depending on a later registry-backed view.

The [capture helper](../src/lib/publication-editions-capture.mjs) and [explicit CLI](../scripts/capture-publication-edition.mjs) read an available committed source A and compare every requested working-source byte with that baseline. Default mode previews. Writing requires the exact preview proposal hash and repeats that proof. A later capture may reuse an unchanged source snapshot only after its complete raw bytes, projection and method pins have been verified against the new baseline. Its original `Source.commit` remains immutable; the new edition records the newly inspected complete `sourceCommit`.

The [append-only checker](../src/lib/publication-editions-append-only.mjs) reads actual Git objects. CI and release require an exact available ancestor base, the complete previous public and service mail closures and all historical source/artifact bytes. A missing or malformed previous tree cannot become an empty bootstrap. The first bootstrap proves both reserved roots absent at a real base. Later changes cannot rewrite or remove old blobs, even by changing only JSON whitespace. Current and previous mail closures are each regenerated from their corresponding public registry and compared exactly; two independently valid but inconsistent roots are refused. Only local offline mode may report an unavailable base, and that result is not release acceptance. These are repository checks, not a guarantee against a privileged history rewrite.

Financial observations preserve their literal source values, units, currency, period, geography, denominator and stock/flow meaning. Comparisons report recorded descriptive changes only where the method and scope permit them. Incompatible inputs return an explicit not-comparable result. Counts of project entries, software releases or editorial work do not measure charity-sector improvement. Unknown remains distinct from zero. No ratings of named charities are added.

The browser proposal desk validates complete fixed public basis bundles against the offered catalog. It does not import the Node-only R4 reducer or independently decide qualification. An explicit selection fetches only the selected bounded bundle; all admitted source and member context remains available. A complete local backup includes all private proposals, notes and unfinished form state. A selected proposal packet contains the selected version and its full pinned public closure, with explicit omissions; it is not a restore backup or a published issue. Neither route uploads local work automatically.

The [local store](../src/lib/client/publication-editions-store.ts) requires Web Locks, exact observed saved bytes and a separate current-memory hash. It prepares and commits the same immutable candidate. Denied storage, corrupt data, quota failure and foreign changes preserve recoverable work and block an unreviewed replacement. Recovery distinguishes the original corrupt value from later observed values; seeing another change requires fresh review. Selecting up to five bases is a ceiling: the complete backup must still fit 2 MiB, without dropping context or private work to fit.

The [issue gateway](../services/newsletter/lib/issue-operations.mjs) accepts only registered immutable issues. Prepare and send each require a fresh fifteen-minute operational acknowledgement under the existing shared administrator bearer. Proofs bind the exact issue/publication/content/registry/transport, a private keyed audience digest and count, and the exact native draft for send. They are not named human review or research qualification. Pending preferences, mismatched native membership, consent-generation changes, transport drift and uncertain correction ancestors stop a new operation.

The gateway durably consumes the proof and commits the `creating` or `sending` checkpoint before one external operation. The successful matching in-flight result alone may finalize `creating → draft` or `sending → accepted`. A lost response or uncertain finalization retains a stop, without retrying create or send, adopting another native identity or resetting history. Reconciliation records a bounded observation of the saved native ID; it cannot authorize another send. SQL protects immutable identity, consumed proofs and stopped states. The original unqualified campaign routes delegate to the same gateway as permanent Letter 1 aliases. Existing accepted and uncertain history remains inspectable when delivery is disabled. Cron performs maintenance, not campaign preparation or sending.
