# Learning portfolio plan

Pre-implementation proposal · October 27, 2026 · AI-assisted · review: draft. No runtime, storage, criteria edition or learning record is created by this plan. The companion [interfaces](LEARNING_PORTFOLIO_INTERFACES.md) define the proposed software boundary. Root review, a committed public contract and a separate implementation assignment are required before code.

## Purpose and limits

Keep studying with the existing course, preserve the criteria used for a deliberately saved portfolio record and let the learner leave with a complete private copy. A later course change must not rewrite an earlier record. Repair the existing course's unsafe save/recovery paths while preserving its final key and version 1 JSON shape.

The output remains self-recorded study. Public answer checks, reading assertions and text length do not assess reasoning, identity or competence. There is no independent assessor, accreditation, professional credential, recognized chapter, fellowship admission or permission to rate charities. No AI assessment, account, provider, upload, submission or message is added. The textbook and questions remain AI-assisted draft material subject to source and editorial review.

## Frozen criteria

Add one initial authored criteria artifact only after implementation is authorized. It captures the actual ten chapters and current lesson definitions, including ordered options, correct indexes, explanations, practice/capstone instructions, limits and thresholds. Retain exact UTF-8 chapter source text and hashes so an old record does not silently open new reading as if it were old. Render archived text inertly; a link to the current textbook is labeled current.

Extract currently embedded capstone instructions into a small authored data definition without changing their wording or gates. Commit that content/extraction as source baseline A. Generate the first criteria artifact from explicit committed A, then commit the artifact and registry as B. Final B is the tested head; A is an honest source anchor and need not contain its own later artifact. Never fabricate an older syllabus or seed a completed learner.

Only known append-only registry definitions are supported. Changing a chapter, source text, unit binding, question, option order, key, explanation, exercise, worked example or threshold requires a new criteria artifact. Unrelated UI/style edits do not redefine criteria. Capture only the inert authored definitions and chapter snapshots: do not hash the entire later UI component, which will embed its own criteria reference. Existing artifacts remain byte-identical and available. A differently shaped curriculum or different v1 input limits requires a new explicit schema; this slice supports ten units, two questions per unit and three choices per question.

## User journey

1. Read the current criteria ID and limits. Existing progress can be recomputed against them, with an explicit notice that its historical binding is unknown. No portfolio record is created by opening the page or passing a check.
2. Study and save through a guarded course adapter. Invalid/dirty form text and failed-save memory remain recoverable, including raw unfinished completion-day text. Ordinary saves must preserve the current validated day and refuse a date change. A supplied legacy date is preserved by the distinct import/restore path; a blank date prints as unknown. Recording or clearing a self-reported day is a separate deliberate action, not a load/import side effect.
3. Preview an explicit snapshot of saved progress, valid unsaved course-store memory or a chosen v1 file. Unsubmitted DOM strings are a different thing: save/apply them separately or select a deliberate file; capture never performs a hidden course write. Valid unsaved store memory can result from a failed save and is labeled honestly. An absent/cleared key with blank validated memory is also unsaved memory with no source-byte hash, even if the adapter's `unsaved` flag is false. Show the selected frozen criteria, exact input hash, persistence state, missing checks, declared date and self-recorded limitations. Require a fresh unchecked criteria affirmation for each reviewed preview; source/file/criteria/target/reload/recovery changes reset it, and restored raw affirmation is never authority.
4. Append a record containing the complete exact input and criteria. Partial records are useful but must say incomplete. A passing record says only **“Self-recorded completion of these checks.”** Its capture instant is distinct from a legacy date and does not witness when learning occurred.
5. Amend deliberately. An amendment pins the current record ID/hash of the same series and the same criteria, requires a reason and appends a new immutable version. The new record retains exact `previousId`/`previousHash`; initial records have both null. Old versions remain visible, and every predecessor hash is validated. A selected packet keeps that reference while omitting ancestor records and cannot reconstruct them. A different criteria version starts a separate series; changing the current editor or criteria cannot retarget an old result.
6. Download a complete portfolio backup or a selected record packet. A manual packet can be labeled a credential proposal or fellowship planning discussion, with exact limitations. It is not submitted anywhere. Nothing writes an applicant, assessment or project into the old partner workspace.
7. Restore separately. A portfolio restore changes only its companion key. Restoring progress from a selected portfolio record is a distinct preview/confirmation under the course key. There is no automatic multi-key migration or claimed atomic transaction across two saved workspaces.

## Storage, bounds and recovery

New companion key and lock: **`charitology.learning-portfolio.v1`**. Course lock: **`charitology.principles-course-v1`**. No other legacy key is read or written. Existing generic `store.ts` remains unchanged; the new course UI uses the new adapter directly instead of relying on the old fallback helpers.

Each store keeps validated memory, generation, state hash and exact observed saved bytes separately. A missing key may create an unsaved blank view; a read error or corrupt/unknown-format key may not. Initial unsupported data is preserved as readable raw text when available, with writes blocked until explicit reviewed recovery. Unknown fields are refused and recoverable, never silently stripped as the old `validCourse()` helper does. Read denial must say bytes are unavailable; it cannot offer an empty substitute as a recovery copy.

Every save, import, reset, restore, undo and reload uses the final-key Web Lock, current memory generation/hash and exact saved-byte comparison, including a fresh pre-preview read. `storage` events warn early but are not the authority. Missing Web Locks permits validated reading/export only; unavailable required hashing permits raw recovery only. Successful reload invalidates undo. Mutable caller inputs/options/previews are copied before queuing/awaiting; late file/hash results cannot replace a newer form.

Quota failures retain a valid unsaved candidate. Retry saves that candidate once, without replaying an event or inventing a date. New work invalidates an older retry intent. Dirty raw forms have separate plain recovery downloads, including when they cannot fit into a valid complete backup. Raw recovery is explicitly not a validated portfolio backup.

| Bound                                   |                                                                                     Proposed exact limit |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------: |
| Known-shape v1 course import/export     |                                             400,000 UTF-8 bytes, including pretty JSON and final newline |
| Frozen criteria artifact                |                                       262,144 canonical UTF-8 bytes; at most 20 retained known artifacts |
| Portfolio records, including amendments |                                                                        10; no automatic deletion/pruning |
| Complete portfolio backup               |                     2,097,152 UTF-8 bytes, including wrapper, export instant, checksum and final newline |
| Raw unfinished portfolio/course form    |                   524,288 canonical UTF-8 bytes; individual raw strings at most 16,384 UTF-16 code units |
| Source JSON admission                   | Maximum nesting 32; duplicate decoded keys, malformed UTF-8, unknown keys and unsafe JSON shapes refused |

The 400,000-byte legacy bound is an intentional expansion of the old UI's 200,000-byte import ceiling, with no format/key migration. All known writer fields at their maximum lengths can exceed 200,000 bytes through JSON escaping: an actual accepted passing probe is 373,841 pretty bytes. A second actual-module probe used maximum-length JSON-escaped strings, false reading assertions, all `-1` answers and the accepted date `9999-12-31`; its complete known shape is **373,881 bytes**, including the newline. Multibyte prose, lone surrogates and quote escaping also round-tripped within 400,000 bytes. These read-only probes did not write progress or add a test fixture. The old permissive validator also accepts unknown extra fields of unbounded size before stripping them; those are **not** included in this guarantee. Strict imports refuse those extras and preserve the raw selected bytes for recovery. Implementation acceptance must retain an actual-module maximum-shape regression. The complete 2 MiB portfolio bound always overrides collection maxima and forbids truncation.

A capture from the live course holds the course lock before the companion lock. The course adapter owns an opaque capture-read binding and a narrow expiring read-lease hook; the companion coordinator owns its opaque live/file previews and private already-locked commit. It rechecks the actual course generation/hash/saved string and companion baseline at the final append, writes only the companion and never reacquires its own held lock. Other code must not take these locks in reverse order. Generic companion prepared commits are draft-only; record appends use the dedicated capture path. File-only capture needs only the companion lock and refuses copied/foreign/consumed previews. The UI guards newer form epochs and disables editing during final commit. Every queued argument/options object is copied and stamped before awaiting. Course prepared metadata is version1 with generation/hash; companion prepared metadata also binds its persisted expected revision. Existing already-open old course tabs do not honor the new guard; rollout instructions must ask people to reload/close those tabs and must not claim retroactive protection.

## Acceptance before completion claims

- Actual current question/option/key/chapter mapping, thresholds and known v1 exports remain compatible. Calendar dates retain the actual old domain; invalid rollover dates fail. The known maximum writer shape fits 400,000 bytes and round-trips; unknown extras, exact bound/one byte over, bad UTF-8, duplicate keys and depth fail before assignment.
- Pure tests use two explicitly synthetic criteria versions. Reordering/changing content without a new artifact fails, and earlier records/criteria remain unchanged. Wrong/unanswered answers, false reading assertions and short/whitespace-only work fail local completion. A supplied complete flag cannot override recomputation.
- Actual graph/history tests cover amendment heads, stale criteria/current-record bindings, unrelated raw drafts, hash tampering, missing references, async mutation and immutable snapshots. No synthetic learner appears as a public real record.
- Course and companion actual-key tests cover concurrent writers, no-event foreign writes, read denial/corruption, unsupported locks/crypto, stale previews, failed clear/save/retry, undo invalidation, mutable queued arguments and exact 2 MiB/+1 complete backups. The other keys remain byte-identical and untouched.
- Mounted UI and a separate real browser journey cover partial work, dirty raw save/download, a blank legacy date, current evaluation versus historical record, explicit capture/amend/restore, failed persistence, print, inert hostile text, keyboard/narrow-screen use and actual downloaded-byte validation. Code tests are not browser proof or learner research.
- Publication copy keeps the independent credential, real assessor process, chapter recognition and fellowship operation gates open. Learner outcome validation requires consenting people/research; this software and its IDs/hashes do not supply that evidence.
