## One closed import contract

The [model](../services/charity-os/lib/field-response-model.mjs) accepts complete original UTF-8 JSON for `charitology-aggregate-service-visits`, version 1, form `aggregate-service-visits-v1`, schema version 1. The file is bounded to 256 KiB and 100 aggregate responses. This is one versioned adapter, not generic Kobo, CSV or arbitrary JSON mapping.

A staff user chooses an existing source connection, current program and visits indicator, then explicitly selects responses. Preview binds those definitions and their revisions. The UI discloses that inspection transmits the full chosen file; the saved historical report retains the reviewed selection and file digest, not the raw file, local path or unselected values. Final outgoing review and acknowledgment precede an explicit commit. Zero remains zero, missing counts remain null, and exclusions retain their reasons. A denominator is retained data; the adapter does not calculate a rate, infer impact or approve evidence.

Selected rows create ordinary unapproved Outcomes observation drafts. The immutable report preserves source identity, mapping, row positions and canonical row hashes, period, unit, geography, counts, missingness, exclusions and initial record references. Canonical row hashes are not original byte-span hashes. Source IDs are scoped by connection. Identical previously retained rows preserve later ordinary edits; conflicting source or mapping changes refuse. Deduplication checks historical reports and current/trash records across modules. A second connection with the same external ID remains independent.

The [commands](../services/charity-os/lib/field-response-commands.mjs), [report store](../services/charity-os/lib/field-response-store.mjs) and current membership/program scope remain authoritative. Snapshot-only roles cannot read the private history. No import grants accounts, consent, approval or provider access. Accepted Retry uses the exact command body/key after fresh authority checks, before new preview expiry/definition checks. A new key is not a Retry. These commands use existing previews, ordinary records and immutable reports; no new table, grant or backup namespace is introduced.

## Recovery and capacity

The [recovery helper](../services/charity-os/lib/field-response-recovery.mjs) validates the reserved report family before persistence and restores it inside the existing workspace transaction. Report ID, title, checksum, payload and original source/mapping organization remain historical. Only the destination row's organization, actor and exact SQL creation time change. Restored observations stay drafts, and historical references may remain orphaned. Native recovery does not restore accepted command receipts, credentials, approval or live source authority. Existing destination FIELD history blocks restore even when the incoming workspace has none.

Repeated native export → restore → export → second restore preserves those historical report values. Absent old packets preserve their previous summaries, counters and projection shape. The frozen legacy projection fixture and malformed-family tests retain this compatibility boundary. Capacity uses actual report-row SQL measurements and the existing native/restore checks. FIELD-only legacy-v2 optional export-audit dispatch is included. No hard cap or reserve was increased. This profile does not prove a new mixed live GROUP/check-in graph, near-limit packet or attainable maximum.
