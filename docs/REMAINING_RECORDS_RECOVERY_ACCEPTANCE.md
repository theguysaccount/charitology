## Preserved formats and behavior

All twenty original keys and native version-1 formats remain: seven research desks, nine partner desks, manuscript, nominations, Depth Census and the complete country-note map. The registry is closed to those exact keys and inert schemas. No arbitrary caller validator, serializer, alternate key or storage-discovery callback is accepted. No automatic migration, shared-service submission, graph synchronization, provider call, mail or money action is added.

Native admission preserves IDs, source strings, date spelling, null/zero distinctions, field and collection order, sparse research drafts and the original calculations. Untouched fields use their admitted original string only while the displayed control remains untouched. The first explicit input/change permanently revokes that field's substitution, including a change back to its initial display or an empty clear. Literal exposed controls have a separate raw-form export.

New-row identity is bound only after complete synchronous admission. An admitted new row retains that identity through a held/superseded save, persistence failure, newer typing, exact Retry and resubmission. A refused candidate creates no dangling ID; a missing formerly saved row is not silently reinserted. A frozen Replication version is never edited: if Retry saves it while newer fields remain, explicit Fork/New is required to establish another version.

Research, manuscript and country notes use a single 250 ms autosave timer with captured view ownership. Native research/manuscript/country exports can overlay the current partial draft outside the engine. Partner kits and native nomination/Depth exports contain admitted records; unfinished fields remain separate. Country's complete native backup includes all notes, while its selected brief remains a separate output. Primary-country navigation must resolve the preceding country's pending save or an explicit discard/reload; comparison and filtering never refill notes.

## Recovery and bounds

Exact-key Web Locks and exact saved-byte comparison coordinate updated clients. Every command binds the owned current view and memory; source changes, edits, newer choices, cancellation and disposal revoke previous authority. One running full replacement and one newest pending replacement bound queued preparation. Caller data/options are detached synchronously, before awaiting hashing or a lock. Missing write capabilities preserve validated read/export access and protected raw bytes.

A failed set/remove retains its exact candidate. Ordinary saves cannot replace it. Reviewed replacement, remove, one guarded Undo and explicit reload are separate actions. Initial protected A and currently observed B remain separately recoverable. Downloading does not clean a form or grant discard permission. Native file input uses one abortable FileReader, a 30-second deadline and immediate revocation before every new choice, including invalid, empty and oversized choices.

Native parsing also enforces the exact schema, duplicate decoded keys, fatal UTF-8 and depth 32. Raw saved-copy recovery is separately bounded at 128,000,000 bytes; raw forms at 1,000,000 bytes. Limits refuse the whole value without truncation. Genuine fixed, ordinary ArrayBuffer-backed Uint8Array input transports bytes only; auxiliary own properties are neither invoked nor copied into authority. Shared/resizable/detached, subclass and custom-prototype substitutes are refused. Native object data remains strict about accessors and decorations.

Count limits remain 200 research records; 250 partner records per collection and 500 total; 100 nominations; 1,000 Depth rows; and the exact 217 country codes. A browser's storage quota or available memory can be lower than the format limit. Large accepted records can therefore remain clearly labeled failed-save memory for export/Retry. Node feasibility reached roughly 1 GiB process RSS with large fictional fixture/source/export allocations; this is not a low-memory-device guarantee.

Persisted browser-history navigation preserves the same session, model, editor identity, hydration pairs and raw fields. It cancels pending timers and revokes queued write/preview authority. Return rereads exact saved bytes and updates status/capabilities without refilling or clearing unfinished forms. An initialization read has no exposed write authority; a return during initialization requests a recheck before first hydration while preserving initial ownership. Ordinary page hiding still disposes. The same narrowly reviewed lifecycle correction applies to the six older general/local OS workspaces through their existing APIs; 35 actual general-desk and 38 actual local-OS groups pass with strict zero, including held initialization, queued writes, exact Retry, native editor/recovery-host preservation and current-token ownership. Independent review repeated all 117 general/OS/Partner groups and reported no remaining finding. These are mounted lifecycle checks; native BFCache behavior is not established by simulated page events. Their earlier published runtime remains a separate historical record.
