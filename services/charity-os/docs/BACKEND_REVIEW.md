# Shared OS backend review

Reviewed 26 October 2026. This was a source and executable regression review of `lib/`, `api/` and `scripts/`. The reviewer changed only this document and `test/backend-review.test.mjs`; the implementation owner made the service fixes. No provider requests, emails, production database mutations or deployments were performed by this review.

The review covered tenant transactions and RLS, membership and program scopes, revision checks, independent approval, historical snapshots, attachment access, reports, delayed jobs, scanner-safe authentication, authenticated remote reads, native source identity, backup restore, and chunked transport. The installed Better Auth magic-link implementation was inspected for hashed-token storage and the consuming verification route. Its actual database/session integration is tested separately in `test-db/runtime.test.mjs`.

## Findings and verification

No P0 issue was identified. No reported P1 remains open in the reviewed code after the fixes below. The following concrete defects were reported to the implementation owner and fixed during review.

| Priority | Defect and consequence | Verified correction |
| --- | --- | --- |
| P1 | A snapshot reader's program scope was checked against the current record only. Moving a record from program A to B could reveal the old A snapshot to a B reader. | Both the current envelope and the historical snapshot must satisfy the reader's scope. Tests cover board and external readers. |
| P1 | Due reminders checked membership existence but not its current role, scope or snapshot visibility. A revoked permission could still leak the current private title by email. | Dispatch reloads membership and the record, applies `visibleRecord`, cancels inaccessible reminders, and uses the visible title. Tests cover removed membership, changed role, changed scope and historical title selection. |
| P1 | Once a document had an approved snapshot, snapshot readers could list and download attachments added later. File upload did not invalidate approval. | Approval freezes file IDs and checksums. Snapshot readers can list/download matching frozen files only. Upload increments revision, clears approval, returns approved content to review and records the last editor while retaining the historical snapshot. |
| P1 | Reference validation checked tenant and target type, but not the actor's access to a target. A scoped participant could link work to an inaccessible program's shift or another restricted module. | Create, edit, approval and transition check every scalar/array target through current visibility. Domain validation still receives the full organization context for capacity and allocation checks. |
| P1 | Editing an approved financial record cleared approval but retained its approved workflow stage. A subsequent transition to active could advance the changed content without fresh review. | Edits to approved/frozen content return to review or the initial state. Advancing from an approval stage requires approval for the current revision. |
| P1 | Restoring into an organization containing only soft-deleted records was treated as restoring into an empty organization. Conflicting IDs remained deleted while the service reported success. | Preview and commit count all stored records, including trash, and refuse this destination. |
| P2 | Report list metadata exposed titles and creator IDs even when detail access would reject the report's modules or program scopes. | List eligibility now checks the frozen report's modules and records before returning metadata. |
| P2 | Backup restore dropped native source identities and connection metadata, so unchanged reimports could create duplicates after recovery. | Validated source identities survive restore. Connection IDs/configuration return in an unconfigured state, without credentials. Reconnection replaces encrypted credentials without changing the identity. Imported approvals and snapshots remain untrusted and reset. |
| P2 | Restore did not share normal attachment type/signature validation or the aggregate file quota. | A shared validator checks allowed MIME types, signatures, UTF-8 text, encoding and content checksums. Restore checks the aggregate 25 MiB file quota. |
| P1 | Valid large module lists, reports and CSV exports could exceed the hosting platform's non-streaming response limit within the 16 MiB structured-record quota. | JSON responses and CSV exports now use readable streams. Tests execute actual list/CSV handlers with over 4.5 MiB of valid module data and verify the decoded result. Organization backups also stream. |
| P1 | A newly added export quota initially rolled back membership revocation and credential disablement when history was full. | Access-control actions use a minimal 1 MiB audit reserve beyond the normal 60 MiB budget. If that reserve is exhausted, they still complete with a redacted operational warning; ordinary mutations stop, while export remains available. Focused tests cover both reserve states and export access. |
| P1 | Source archives were excluded from the current-workspace budget. Empty backups and no-op import journals could retain unbounded committed preview payloads. | Organization-locked preview creation and commit now enforce separate limits: 4 pending previews/128 MiB and 32 committed previews/128 MiB, across all preview kinds. Postgres measures retained JSON text bytes. Only expired uncommitted previews are cleared; existing committed source payloads remain downloadable. |

`test/backend-review.test.mjs` contains 21 passing scenarios, with 4 additional archive-capacity scenarios in `test/archive-quota.test.mjs`. The current combined server/browser command, `node --test test/*.test.mjs public/*.test.js`, passes 89 tests. The focused tests call the actual visibility, handler, jobs, remote-read, upload, file and restore functions, using synthetic records and mocked database/HTTP boundaries. They include a 5 MiB streamed JSON round trip, actual large module list/CSV handlers and Unicode backup chunks split inside a UTF-8 character. They are correctness regressions; they are not live-provider or deployed transport-limit/throughput proofs.

`test-db/archive-quota.test.mjs` separately passed against actual Postgres in a temporary schema in 59 seconds. It verified Postgres JSON byte sizing, the constrained role's tenant isolation, a later import failure rolling back the archive transition, and two simultaneous commits competing for the final archive slot. Only one committed. All synthetic source payloads, including expired committed sources, were preserved until the test schema's cleanup. No provider requests or email occurred.

## Security boundaries inspected

- Organization mutations serialize on a transaction-scoped organization lock. Membership and record revision are checked in that transaction. The last owner cannot be removed or demoted without another owner. Invitation acceptance locks the invitation and binds it to the authenticated email address.
- Tenant tables enable and force RLS. Record data is visible to the application role only under the transaction's organization context. The application must use the separate non-superuser, `NOBYPASSRLS` connection; owner credentials remain migration-only. The actual database integration asserts these role properties and verifies an empty result without tenant context. This review did not independently repeat that integration.
- Raw Better Auth consuming GET routes are not publicly dispatched. Email links open a confirmation page; deliberate form POST invokes the verification handler internally. The opaque origin exception is confined to this token-bearing confirmation. Application mutations require exact origin and a session-bound CSRF value.
- Remote reads resolve all addresses, reject non-public results, pin a checked address into the HTTPS request and preserve the hostname for TLS. Redirect responses are rejected rather than followed with credentials. Response size and timeout bounds are enforced. The regression executes this transport with a synthetic resolver/requester; no external account was contacted.
- Native import previews are stored server-side, tied to the organization/actor and checked against the workspace revision before an atomic commit. Source identity has a database uniqueness index. Changed remote rows become conflicts rather than silent overwrites.
- Snapshot readers cannot fetch working history or comments. Full backup, import archives, audit and connection management require administrators. Connection responses omit encrypted credentials. Backup provenance does not become trusted approval, membership or audit authority.
- Delayed mail has its own durable job identity, and the separate newsletter relay preserves a delivery intent beyond the provider's idempotency window. An ambiguous attempt is not automatically resent. Provider acceptance is not an inbox-delivery guarantee.

## Release follow-through

Connection creation and restore now share the same 30-connection bound. Deleted documents' bytes are exported separately as `trashFiles` and retained in the private source archive. Source history, comments, reports and trash retained in an original import archive remain provenance; they are not automatically promoted into new trusted live records. Current workspace exports do not recursively embed earlier archive payloads; download and retain those archives separately.

The reported P2 dispatcher starvation issue is addressed by a shared 45-second start/mail budget and least-recently-visited tenant ordering. The mail request clamps its deadline and the dispatcher stops starting jobs when its safety margin is reached. Database operations and hosted execution still require separate operational monitoring; this review does not claim a delivery-time service level or unlimited throughput. The documented hosted schedule remains daily at 07:00 UTC.

Before release, use the separate actual-Postgres integration, deploy-time role/configuration checks, browser verification and controlled transactional delivery evidence. The focused tests above do not substitute for those checks. This is an AI-assisted engineering review, not a security certification.
